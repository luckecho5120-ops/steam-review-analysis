# 标签与标注规范

## 两级标签字典

下表为初始字典。结合具体游戏可增减，但必须记录变更并重标受影响记录。

| 一级 | 二级 |
|---|---|
| 战斗与动作体验 | 技能与招式、操作响应、判定与命中、打击反馈、战斗交互、视角与锁定、小怪种类与配置 |
| BOSS 设计 | 机制与阶段、动作可读性、交互与反制、难度与容错、种类与重复度 |
| 养成与 Build | 武器差异、技能成长、装备搭配、Build 多样性与平衡、成长反馈 |
| 地图与探索 | 地图结构、探索奖励、路线引导、空气墙与边界、跑图与检查点 |
| 性能与适配 | 帧率与卡顿、崩溃与启动失败、存档与流程 Bug、其他 Bug、画质与显示、输入延迟、手柄与键鼠适配 |
| 叙事与视听 | 剧情与文案、美术、音乐音效、配音、本地化 |
| 商业与其他 | 价格与内容量、版本及购买问题、其他明确问题 |
| 无法归因 | 缺少具体体验内容、无关内容、无法理解 |

“无法归因”主要是内容状态：只有整条无明确体验内容时才归入该池。一条评论部分可归因时保留其有效片段，模糊片段不虚构标签。

## 易混边界

- 操作响应：按键后动作反馈等体验；输入延迟：明确涉及延迟现象。原因不明时先记体验，不推断是设备、性能或设计造成。
- 判定与命中：攻击/受击范围与碰撞公平性；打击反馈：音效、震动、硬直等带来的打击感。
- 战斗交互：攻防、闪避、格挡等一般交互；BOSS 交互与反制：明确指向 BOSS 的反制窗口或互动机制。
- 视角与锁定：镜头跟随、目标切换、遮挡；不要因为发生于 BOSS 战就自动打 BOSS 机制标签。
- 小怪种类与配置：普通敌人种类与组合；BOSS 种类与重复度：BOSS 内容差异与复用。
- 技能与招式：招式本身的表现和使用；技能成长/Build：解锁成长、搭配及构筑选择。
- 画质与显示：清晰度、渲染或显示异常；美术：风格、设计与审美。
- 文本翻译问题归本地化；故事节奏或角色塑造归剧情与文案。
- 同一证据确有两个独立问题可多标；近义表述不通过多标膨胀计数。新增标签补全定义、包含项、排除项和示例。

## 标注记录

每个体验片段记录：review_id、segment_id、原文证据、译文、一级/二级标签、片段倾向（正向/负向/混合/不明确）、严重程度、原因关系、置信状态、复核状态、字典版本。

推荐态度来自原始好差评字段，不从文字语气重新推断。严重程度：阻断游玩 / 显著影响体验 / 一般问题 / 无法判断。原因关系：明确导致差评 / 负面提及但因果不明 / 正向认可 / 推测待核验。分析者推测与玩家明确陈述分开保存。

例：“打击感好，但锁定乱跳，第二个 BOSS 场景掉帧。”

- 打击反馈：正向。
- 视角与锁定：负向，严重程度视上下文判断。
- 帧率与卡顿：负向，场景备注第二个 BOSS；不能据此认定 BOSS 机制存在问题。
- 没有明确表示这些问题决定差评时，不标为已确认差评原因。

“启动不了”标崩溃与启动失败、疑似阻断，交 QA 核验；“不好玩”保留推荐态度但不猜测战斗、剧情或难度原因。

## 质检

试标覆盖主要语言、好差评和时长分组；约定抽检比例、分歧处理及通过标准。可采用双人/独立复核或单人回查，不强制增加不必要人力。抽检记录总数、错误类别、修订和受影响范围。严重问题、歧义、低置信度及报告引用逐条核验。

AI 标注保存模型、提示词、术语表和字典版本。自动标注不等于人工确认，不报告未实际完成的复核。系统性偏差需修正规则并重跑相应范围，不能只修改图表中的几条例子。
